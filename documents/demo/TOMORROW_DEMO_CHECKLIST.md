# Tomorrow's CIO demonstration checklist

## Before the meeting

- Close unrelated applications, notifications, recent-item views and private workspaces.
- Connect power and confirm the browser is available.
- From this project folder, run `.\start-demo.ps1`.
- Open `http://127.0.0.1:8017/` and confirm the ABL-inspired overview loads.
- Open `http://127.0.0.1:8017/workbench` and confirm the five proof-point buttons appear.
- Open `http://127.0.0.1:8017/cheatsheet` in a second tab.
- Reset the synthetic demonstration before the meeting.

## Recommended route

1. **Overview:** explain the operating model—make AI useful, then keep it useful.
2. **Choose proof 01:** show the matter-opening problem in terms of a lawyer unable to work or record time.
3. **Choose proof 02:** run one normal support case and one hard stop.
4. **Choose proof 03:** show that Harvey use cases have controlled pilot designs; do not claim outcome evidence.
5. **Choose proof 04:** run the prompt regression and show that a recommendation cannot activate itself.
6. **Choose proof 05:** close on responsible use, total cost and stop decisions.

## Best cases to run

- **Approved matter not yet available:** evidence, proposal and named approval.
- **Replay could create a duplicate:** reconcile rather than recreate.
- **Restricted matter access:** information-barrier authority cannot be overridden.
- **Document add-in unavailable:** safe general-IT guidance and data minimisation.

## Claims to make

- The support workflows are functioning synthetic demonstrations.
- The Harvey component proves use-case and pilot readiness, not business benefit.
- Prompts and skills preserve repeatable practice.
- Regression and named approval govern change.
- Quality, safety, useful adoption and total cost determine whether to continue.

## Claims not to make

- This is ABL's actual architecture, data, configuration or performance.
- Harvey has already improved quality, saved time, increased profit or changed a court outcome.
- Review definitions are already running as production scheduled automations.
- A synthetic time difference is realised financial value.

## If something goes wrong

- Refresh the current page once.
- Return to `http://127.0.0.1:8017/workbench` and choose the proof again.
- If an interaction was already run, use **Reset synthetic demo** in the full evidence workbench.
- Continue with the proof pages and the Demo's Rational; the narrative does not depend on every interaction running live.

## Final close

> The point is not to add AI everywhere. It is to create a repeatable way to identify useful opportunities, implement them with controls, reuse what works and stop spending when the evidence no longer supports the capability.
